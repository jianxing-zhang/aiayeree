# LangGraph Studio 图片上传不识别 —— 三次踩坑实录

> 现象：在 LangGraph Studio 上传图片，agent 一直说"无法识别图片"，但 notebook 里直接调用 DashScope 多模态是好的。

---

## 根因一览

| # | 坑 | 位置 | 后果 |
|---|----|------|------|
| 1 | **graph 入口配错**：`langgraph.json` 指向了 `agent`（纯 ReAct Agent）而不是 `graph`（自己写的 StateGraph） | `langgraph.json` | 带 `vl_ocr_node` 的 StateGraph 根本没被执行 |
| 2 | **图片格式不兼容**：只认 `{"type": "image_url", "image_url": {"url": "..."}}`，Studio 实际传的是 `{"type": "image", "data": "<纯base64>"}` | `vl_ocr_node` | 图片 chunk 被静默跳过 |
| 3 | **base64 没补前缀**：Studio 给的是裸 base64（`iVBORw0KGgo...`），DashScope 需要完整的 data URL（`data:image/png;base64,iVBOR...`） | `vl_ocr_node` | 即使格式对了，DashScope 也可能认不出 |

---

## 根因 1：graph 入口配错（最致命，直接废掉整个 StateGraph）

### 现象

修改 `personal.py` 里的 `vl_ocr_node` 加了无数 `print` / `logging.info`，Studio 日志里**一个都没出现**。每次 run 只有 **1 次** DashScope 调用，没有 VL OCR 的那次。

### 根因

`personal.py` 里有两个 graph 对象：

```python
# 对象 A：create_agent 返回的 ReAct Agent（只有 model→tools→END，没有 vl_ocr_node）
agent = create_agent(model, tools=tools, system_prompt=system_prompt)

# 对象 B：我自己用 StateGraph 构建的（有 vl_ocr → run_agent → END 两个节点）
graph_builder = StateGraph(AgentState)
graph_builder.add_node("vl_ocr", vl_ocr_node)
graph_builder.add_node("agent", run_agent_node)
graph_builder.add_edge(START, "vl_ocr")
graph_builder.add_edge("vl_ocr", "agent")
graph_builder.add_edge("agent", END)
graph = graph_builder.compile()
```

但 `langgraph.json` 配置的入口是 **`agent`**：

```json
{
  "graphs": {
    "chief_agent": "./app/agents/personal.py:agent"  // ❌ 错了
  }
}
```

Studio 加载的是 `create_agent` 那个 ReAct Agent，内部根本没有 `vl_ocr_node`！所以不管怎么改 `vl_ocr_node`，Studio 永远不会执行它。

### 修复

```json
{
  "graphs": {
    "chief_agent": "./app/agents/personal.py:graph"  // ✅ 指向自己的 StateGraph
  }
}
```

### 教训

- **配置文件是入口**，Python 里同时存在多个 graph 对象时，必须确认 `langgraph.json` 指向的是哪个
- LangGraph dev server 的 **watchfiles** 只能热更 Python 代码，`langgraph.json` 改了需要**重启 dev server**

## 根因 2：图片格式不兼容（graph 跑起来了但图片没被认出来）

### 现象

graph 跑起来了，日志里 `[VL_OCR]` 也出现了，但每次都是：

```
[VL_OCR] ===== 收到消息 =====
[VL_OCR] last_msg type=HumanMessage, content type=list
[VL_OCR] content repr: [{'type': 'text', 'text': '就用图片'}, {'type': 'image', 'data': 'iVBORw0KGgoAA...'}]
[VL_OCR] text_buf=['就用图片'], img_url=<NONE>    ← 图片没识别出来！
[VL_OCR] 未识别到图片，原样透传
```

### 根因

`vl_ocr_node` 原来只认 LangChain OpenAI 标准格式：

```python
# 代码里只处理这一种
elif chunk.get("type") == "image_url":
    img_url = (chunk.get("image_url") or {}).get("url")
```

但 **LangGraph Studio 前端上传图片后序列化的格式是**：

```python
{'type': 'image', 'data': 'iVBORw0KGgoAA...'}  # ← 这才是实际格式！
```

`type` 是 `"image"` 不是 `"image_url"`，图片数据在 `data` 里不是 `image_url.url`。

### 修复

在 `vl_ocr_node` 里新增 Studio 专用格式的处理，放在最前面优先匹配：

```python
# ===== LangGraph Studio 上传图片实际格式 =====
elif chunk.get("type") == "image" and "data" in chunk:
    raw_b64 = chunk["data"]
    ...
```

### 教训

- **永远不要假设前端传什么格式**，一定要打印实际收到的 content repr
- 格式兼容要从"只认一种"扩展到"常见格式全认"

## 根因 3：base64 没补 MIME 前缀（最后一公里）

### 现象

格式对上了，`img_url=<found>` 也打出来了，但 DashScope 返回 400：

```
resp.status_code=400, code=InvalidParameter, 
message=The image length and width do not meet the model restrictions.
```

### 根因

Studio 给的 `data` 是**纯 base64 字符串**（`iVBORw0KGgo...`），没有 MIME 前缀。DashScope 的多模态接口需要完整的 data URL：

```
data:image/png;base64,iVBORw0KGgo...
```

而且 PNG 和 JPEG 前缀不同，需要识别：
- `iVBORw0KGgo` → PNG
- `/9j/4AAQSkZJRg` → JPEG

### 修复

```python
elif chunk.get("type") == "image" and "data" in chunk:
    raw_b64 = chunk["data"]
    if isinstance(raw_b64, str):
        if raw_b64.startswith("data:"):
            img_url = raw_b64
        else:
            # 自动识别 PNG / JPEG
            mime = "image/png" if raw_b64.startswith("iVBOR") else "image/jpeg"
            img_url = f"data:{mime};base64,{raw_b64}"
```

## 完整修复后的格式兼容列表

| # | 格式 | 来源 |
|---|------|------|
| 1 | `{"type": "image", "data": "<纯base64>"}` | **LangGraph Studio 上传图片** ← 主要修复对象 |
| 2 | `{"type": "image_url", "image_url": {"url": "..."}}` | LangChain OpenAI 标准 |
| 3 | `{"url": "data:image/png;base64,..."}` | 其他前端直接传 data URL |
| 4 | `{"image": "..."}` | DashScope 原生 |
| 5 | `{"image_url": {"url": "..."}}` | 无 type 字段的情况 |
| 6 | `{"url": "http.../data:..."}` | 无 type 字段但有 url |

## 调试方法论（踩坑出来的）

1. **先确认 graph 入口**：改了代码没生效 → 先看 `langgraph.json` 指的是谁
2. **print / logging 都不出来时**：用 `sys.stderr.write` + `flush()`，LangGraph dev server 重定向了 stdout 和 logging
3. **永远打印实际收到的 content repr**：不要猜前端传什么格式，让数据说话
4. **watchfiles 热更 Python 代码有效**，但 `langgraph.json`、venv、logging 配置改动需要重启 dev server
